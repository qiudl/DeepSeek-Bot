# 消息宽度

- 日期：2026-10-22
- 相关：#380

## 为什么

Bot 回复的气泡最宽写死在 560px。宽屏下正文列是 960px，Bot 气泡只占 58%，比用户气泡（列宽的 70.2%，674px）还窄。长回答、代码块和表格因此被挤成一窄条，频繁换行。#380 希望能调宽度。

取舍：

- 气泡跟着正文列按比例走，不再有像素上限，Bot 和用户的气泡用同一个比例，默认 80%。
- 宽度用滑块按百分比调，不填像素：换窗口大小、打开右侧面板时仍然成比例。几档预设太粗，滑块能调到每个人顺手的宽度。
- 和主题、强调色、Bot 动画一样存在团队设置里，所有设备共用。
- 不改正文列本身（960px，见 #28）。

## 已定的行为

- 设置 → 通用 → 外观里有「气泡宽度」滑块：50%–100%，每格 5%，默认 80%，旁边显示当前百分比。拖动停下 350ms 后保存（和自定义强调色一样）；还没保存就关掉设置，也照样保存。
- 气泡宽度是正文列宽的百分比，管所有气泡：Bot 气泡、思考过程和用户气泡，私聊、群聊、Bot 之间的对话框都一样。
- Bot 气泡右侧总是留出 82px 给悬停工具栏（6px 间距，加上三个 24px 按钮和它们之间 2px 的间隔），所以宽度调到 100% 时，Bot 气泡是整列宽减 82px。群聊里带头像的消息按（列宽 − 30px）的比例算，再加上 30px 的头像列。
- 服务端只收 50–100 的整数 `width`，其他值报错；默认值 80 不存。页面认不出的值按默认处理。
- 宽度写成 `body` 上的 `--bt-msg-w`（0.5–1）。拿到团队状态之前，先用本机缓存的上一次设置，避免先闪一下默认样式。

## 不做什么

- 不提供像素宽度。
- 拖动时不实时改聊天区的样式；松手后保存，再跟着团队状态变化。
- 不改正文列宽，也不恢复 DSH 的拖动把手（#28）。
- 不按设备分开保存。

## 已知限制

- Bot 气泡最宽到整列宽减 82px：960px 的列大约在 91% 封顶，再往右拖只有用户气泡还在变宽。手机这类窄屏上更早封顶。
